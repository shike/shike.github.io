## 页面结构与视觉设计

### 区块位置

“著作 / Books”位于 Ventures 之后、About 之前。该位置让书籍承接业务实践，同时保持书籍与商业产品之间清晰的信息层级。

固定导航增加“著作 / Books”锚点，目标为 `#books`。中英文切换继续使用现有 `data-en` 机制，移动端导航沿用当前汉堡菜单行为。

### 书籍卡片

桌面端使用两列等宽卡片，移动端改为单列纵向排列。每张卡片包含：

1. 书籍封面
2. 中英文书名
3. 一句话简介
4. “在 GitHub 阅读 / Read on GitHub”外链

卡片沿用当前页面的边框、圆角、留白、字号层级和强调色，不引入新的视觉体系。封面保持书籍比例并使用固定尺寸约束，避免加载时布局偏移。

### 封面资源

将两本书的封面复制到站点本地目录：

- `assets/books/ai-coding-cover.jpg`
- `assets/books/fde-cover.svg`

页面不直接引用 GitHub Raw 图片，避免第三方图片加载失败、跨域可用性和性能波动。封面保留来源仓库许可信息，不进行画面裁剪或内容修改，仅按页面实际展示需求缩放。AI Coding 仓库中的 `promotion/cover.png` 实际包含 JPEG 字节，因此本地副本保持 JPEG 格式，等比例缩放为 896×1200、质量 85，并使用 `.jpg` 扩展名；在高分屏下仍高于实际展示分辨率，同时将资源体积控制在约 132 KB。

### 静态内容流

所有产品和书籍内容继续硬编码在 `index.html`，不增加 JSON 数据文件、构建工具或运行时接口。浏览器只加载本地 HTML、CSS、JavaScript 和图片资源；点击书籍或产品 CTA 时再跳转到相应外部网站。

### 外链与错误处理

- Liora Moon 与两本书使用 HTTPS 链接
- 外链在新标签页打开，并使用 `rel="noopener noreferrer"`
- 不通过前端脚本请求 GitHub API，因此 GitHub API 限流或不可用不会影响首页渲染
- 所有封面使用本地资源，并声明 `width`、`height`、`loading="lazy"` 和准确的 `alt`
- 即使外部链接暂时不可访问，卡片正文和封面仍可正常展示
